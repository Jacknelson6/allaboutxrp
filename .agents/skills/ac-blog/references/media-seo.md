# Media and image SEO

Build a manifest with clientId, local asset path, source URL, rights basis,
capture date, depicted product/version, placement, dimensions, alt and caption.
Only use authentic logos and screenshots; distinguish UI capture from vendor-site
capture. Label conceptual diagrams honestly. Never fabricate product evidence.

## Source real images

Prefer client-owned or official assets when illustrating the client's work, people,
products, or results. For topical illustration, search a permitted licensed catalog
through EGOLITE for suitable real photography before defaulting to generated images
or placeholders. Envato Elements and Artlist are possible providers only where
owner policy and account entitlements permit them; never override an owner ban.
No subscription is required to plan or draft. Use verified client assets or another
approved licensed source when a provider is unavailable. Stock is illustration, never evidence of client work or a
substitute for genuine product screenshots. Honor the client's asset policy.

Use Envato Elements' photo catalog for still photography. Check asset type and
AI labels on both services; exclude generated assets when sourcing real imagery.
Artlist's stock catalog is footage-focused, and its AI Image tool is not real
photography. If using a still from Artlist footage, download the licensed original
clip first and verify that current rights cover the intended still-image use;
record the clip ID and frame timecode. If that use cannot be verified, choose a
licensed photo elsewhere. Never capture a frame from a watermarked preview.
See Artlist's [footage catalog guide](https://help.artlist.io/hc/en-us/articles/29595878738589-Browsing-Artlist-s-Footage-catalog)
and [download guide](https://help.artlist.io/hc/en-us/articles/29596510418461-Downloading-Artlist-s-assets);
recheck the current catalog and rights during the actual sourcing run.

Load the installed ego-browser skill and use an agent task space, preserving the
user's existing sessions and authentication. Search using the article's subject,
audience, and intended placement. Inspect the candidate's live asset page, visual
fit, and current license and account entitlement. Follow the site's observed UI;
do not assume button names, download APIs, license terms, or that a signed-in account
covers the intended client use. Complete any required project registration only
within the authorized scope. Paid assets, upgrades, or new charges need approval.

Download the licensed original using the site's supported flow and verify the
actual local file. Do not save search thumbnails, watermarked previews, or browser
screenshots of stock as final images. Inspect the original before making derivatives.
Keep a media-manifest entry for each selected asset: vendor, asset page URL and ID,
creator, access/download date, client and article/project, rights basis and retained
license/entitlement evidence, original download path, edited output paths, placement,
dimensions, alt, and caption. Keep credentials out of the manifest. A download alone
does not establish publication rights.

If access, entitlement, rights, or a suitable image cannot be verified, record the
specific gap and use an approved client/official asset, another verifiably licensed
source, or a clearly labeled diagram when it serves the article. Leave an explicit
media gap when no suitable option exists; do not silently substitute an unlicensed
preview or represent a generated image as a real photo.

## Prepare and verify

Use descriptive filenames and accurate alt text, with natural relevant terms.
Do not keyword-stuff alt or repeat captions unnecessarily. Decorative images may
have empty alt. Logo alt identifies the brand; screenshot alt explains the view.
Captions explain what a reader should learn and identify provenance when useful.

Self-host approved images where practical. Keep clean SVG logos when appropriate;
compress raster screenshots as WebP/AVIF without making UI unreadable. Set dimensions,
responsive sizes/srcset where useful, lazy-load below-fold media, preserve aspect
ratio, and avoid lazy-loading the LCP image. Reserve video dimensions.

Verify image content types, crawlability, URLs, alt, captions, social image and
Article image agreement. Social artwork should be topic-specific and at least
1200 by 630. Check image-sitemap discovery where needed. Do not claim metadata or
EXIF fields provide guaranteed ranking gains.

Capture real browser evidence only with EGOLITE, preserving all user state.
Sanitize sensitive dashboard information before publication. Reuse client assets
only within their permitted scope. Validate at mobile, tablet and desktop sizes.
Visually inspect the actual selected files and their rendered crops at those sizes:
the subject must remain legible and relevant, with no watermark, accidental sensitive
detail, misleading context, or crop that removes essential information. Verify the
hero and social preview separately; passing URL and dimension checks is insufficient.
